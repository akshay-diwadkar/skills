# scope-issue 5.0.0: epic-aware issue-scope contract v2

`scope-issue` 5.0.0 seals issue-scope-contract v2 handoffs. Given one explicit user task and one epic/umbrella GitHub issue, it selects and narrows exactly one ready child and seals one `issue-handoff.md` for `plan-change`, or preserves an honest non-selection state across eight terminal statuses (`plan-ready`, `needs-info`, `blocked`, `close-candidate`, `needs-decomposition`, `no-ready-issue`, `epic-complete`, `selection-tie`). Selection and narrowing are two explicit stages; non-selected candidates need no deep local evidence; a dirty checkout cannot seal readiness or close evidence; status evidence flags, questions, blockers, and selection records are mutually exclusive per status; and a declined child override may be recorded without being selected. Existing v1 invocations run in explicit v1 compatibility with no child selection. `plan-change` intake of v2 receipts is a required follow-up; v1 handoffs remain consumable today.
