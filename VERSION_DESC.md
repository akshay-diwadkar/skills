# scope-issue 5.0.0: epic-aware issue selection and non-selection contract

`scope-issue` 5.0.0 redefines its handoff contract as epic-aware (issue-plan contract v2). Given one user task and one epic, the skill inventories candidates with `CAND` readiness and evidence-cited basis, selects exactly one ready child in a `SEL` record, and narrows only that child (`SC`, `F`, `D`, `C`) — or preserves an honest non-selection status: `needs-info`, `blocked`, `close-candidate`, `needs-decomposition`, `no-ready-issue`, `epic-complete`. The sealed `issue-handoff.md` receipt stays wire-compatible with `plan-change` and `implement-plan` (kind `issue`, version 1); the schema advances only in `metadata.contract_version: 2`. A new `scope_inputs.json` input carries the immutable task/epic/override/exclusion anchors, the fetched snapshot is the sole source for candidate membership, and every validation rule now comes from the JSON schema: record placement in contract-ordered sections, tie-breaker obligations, checkout freshness and dirtiness, and non-empty status evidence.
