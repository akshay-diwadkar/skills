# Knowledge Contract

Source is authoritative. The knowledge directory contains only deterministic machine artifacts: `manifest.json`, `repo-map.json`, `symbols.json`, `relationships.json`, and catalogued symbol shards. It contains no Markdown orientation artifacts.

After a successful CLI build or refresh, `AGENTS.md` and `CLAUDE.md` each contain one managed MAP-CODEBASE reference to the resolved knowledge directory, including a custom `--output` path. Missing instruction files are created and user-owned text outside the block is preserved. The per-file `<!-- OPT-OUT MAP-CODEBASE -->` marker skips that file; `link-docs` explicitly reapplies the same behavior.

`fresh` means root artifacts and listed shard hashes are valid and no relevant indexed file changed. Revision, branch, dirty state, and configured untracked metadata are compared explicitly; any metadata-only difference rewrites only `manifest.json`. The resolved knowledge directory never participates in those comparisons, including when selected with `--output`. Git status uses a normal diff when available, inventory recovery when the stored revision is unavailable, and filesystem inventory only when Git is unavailable. Unchanged inventory recovery updates metadata only; changed recovery requires a safe full rebuild. `partially-stale` has a safe changed-file delta. `stale`, `missing`, and `invalid` require a full rebuild; refresh takes that rebuild path before loading an existing manifest. Schema/config/extractor changes, unsafe artifacts, repository-wide configuration changes, and configured changed-path-ratio escalation also require full rebuild.

Initial builds include safe untracked files by default, excluding ignored, generated-as-configured, binary, oversized, secret-sensitive, unsafe, out-of-scope, and knowledge-output files. With `include_untracked = false`, build, status, refresh, dirty state, and explicit changed paths all exclude untracked files. Resolver phases are bounded; each task has a deterministic primary owner and optional secondary constraints, active configuration keys receive ranked bounded ranges, and test/import evidence always describes the returned target's one-hop relationship. It loads only selected shards internally and consumers verify returned source before acting. Workflow generation remains explicit opt-in and source remains authoritative.
